Scanned PDF vs Text PDF

Two PDFs can look identical on screen and behave completely differently. One contains real text that you can select, search and copy. The other is a set of photographs of pages. Almost every surprise people have with PDF tools, such as "why can I not copy this text", "why did the compressed file stop being searchable" or "why did text extraction return nothing", traces back to this one difference.

The two kinds of PDF

A text PDF (sometimes called digital or native) is produced by software: a word processor's "save as PDF", a spreadsheet export, an online invoice, a report generator. Characters are stored as text with fonts, and the layout is described mathematically. These files are usually small, stay sharp at any zoom level, and can be searched.

A scanned PDF is produced by a scanner or a phone camera. Each page is stored as an image. The computer does not know there are words on it; it only knows there are pixels. These files are larger, and if you zoom in far enough, letters become blocky. Some scanners add an invisible text layer using optical character recognition (OCR) so you can search the image. That hybrid is common in office scanners, and it behaves like a scan when processed, but with text layer extras.

A ten-second test

  1. Open the file in any viewer and try to highlight one word with the cursor. Highlights that follow single words mean text; a highlight that grabs the whole page or nothing at all means an image.
  2. Press Ctrl+F (Cmd+F on a Mac) and search for a word you can see. No hits, in a document that clearly contains the word, indicates a scan without OCR.
  3. Zoom to 400 percent on a letter. Crisp edges mean text. Square pixels mean an image.
  4. Look at the file size. Ten pages of ordinary text at 5 MB or more is probably scanned.

What it means for each tool

Tools that work the same on both kinds. Merge, split, extract pages, remove pages, reorder, rotate, crop, page numbers, watermark and metadata move or annotate whole pages. They do not re-render the content, so a text PDF stays searchable and a scan stays a scan. Cropping only changes the visible window, so cropped-away content remains in the file.

Tools that turn pages into images. The compressor and the grayscale converter draw each page onto a canvas in your browser and save it as a JPEG inside a new PDF. For a scan, that is a small step, as the pages were pictures anyway. For a text PDF, it is a big change: searchable, selectable text is replaced by a picture of the text, links and form fields stop working, and accessibility is lost. The result is often smaller for scans and larger for tiny text files, and the compressor will tell you when it is not worth it. The same applies to PDF to JPG, which by its nature outputs images.

Tools that need real text. The PDF to Text tool reads the text stored in the file. On a text PDF it returns the words, page by page. On a scan with no text layer it finds nothing, because there is nothing to read; that needs OCR, which PDF Engine does not provide.

Tools that need form fields. Flattening a form only works on genuine fillable fields. A scanned form is a flat picture already, with nothing to flatten.

Tools that create scans. JPG to PDF produces image-only pages by definition. A PDF built from photos is a scan in the sense of this article, however good the photos.

Choosing the right source file

If you have a choice, keep the text version for anything you will edit, search or quote, and use a scan only where you need the visual evidence of a signed page or a stamped certificate. A common and sensible pattern is to send the text version of a report with a scanned signature page merged in at the end. When a scan is all you have, take care to scan at a readable resolution in the first place, since no later step can add detail that was never captured: 200 to 300 dpi is typical for documents, and the page should be flat, evenly lit and straight.

Practical consequences and habits

  • Compress last and only when you must. If size is an issue with a text PDF, delete pages or send in parts first, as discussed in preparing a PDF for email and upload limits.
  • Keep the text original. Before using any image-based tool on a searchable PDF, store the untouched file.
  • Do not expect rotation or cropping to change the type. They do not.
  • Check what a recipient needs. Some institutions require searchable PDFs for accessibility reasons, others only care about the look.
  • Do not assume a scan is private by default. It can contain the same sensitive details as a text file, and in image form they are harder to spot. See PDF privacy before you share.

Mixed documents

Real-world files are often mixed. A merged application may have six text pages and three scanned pages. The tools that copy pages treat each page as it is, so the text pages remain searchable and the scanned pages remain images. The image-based tools convert everything, so one run of compression turns the whole file into pictures. If you need to compress only the scanned part, split it out, compress it, and merge it back with the text pages, as described in the merge guide.

Why a scan with OCR is still a scan

Office scanners often make "searchable PDFs" by laying invisible text over the page image. Searching works, but the image is what you see, and the hidden text can contain recognition errors such as an O read as a zero. Treat the visible picture as the document of record, and be careful when copying numbers out of such files: compare them to what is on the page before you rely on them.

Short FAQ

Is a phone photo of a page a scan?

For these purposes, yes. It is an image with no text.

Can PDF Engine make a scan searchable?

No. It has no OCR function.

Why is my text PDF bigger after compression?

Because pictures of text take more space than text itself.
